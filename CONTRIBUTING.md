# Contributing to SaaS Metrics Dashboard

Thank you for your interest in contributing to SaaS Metrics Dashboard.

This project aims to provide a simple, transparent, and useful open-source
dashboard for understanding common SaaS business metrics.

## Ways to contribute

Contributions are welcome in areas including:

- Bug fixes
- Accessibility improvements
- Documentation
- UI and responsive-design improvements
- Additional SaaS metrics
- Data import and export
- Testing
- Performance improvements
- Metric methodology and formula reviews
- New visualization features

## Getting started

1. Fork the repository.
2. Clone your fork.
3. Create a branch for your change.
4. Make and test your changes.
5. Commit your work with a descriptive commit message.
6. Push the branch to your fork.
7. Open a pull request.

Because the current dashboard uses HTML, CSS, and JavaScript without external
runtime dependencies, you can run it by opening `index.html` in a modern web
browser.

## Development principles

Please keep contributions:

- Easy to understand
- Accessible where practical
- Responsive across desktop and mobile
- Free of unnecessary dependencies
- Transparent about how metrics are calculated
- Clearly documented

## Sample data

All demonstration data included with the repository must be clearly identified
as synthetic or sample data.

Do not present fictional values as real company performance, project adoption,
downloads, users, customers, or community activity.

## Metric changes

If you modify a financial or SaaS metric formula, explain the methodology in
your pull request.

Where multiple accepted definitions exist, document which definition the
dashboard implements.

## Pull requests

A useful pull request should include:

- A concise description of the change
- Why the change is useful
- Testing performed
- Screenshots for meaningful visual changes, when applicable

Keep pull requests focused when possible.

## Issues

Before opening a new issue, check whether a similar issue already exists.

Bug reports should include enough information to reproduce the problem,
including browser/device information when relevant.

## Security

Please do not publicly disclose security vulnerabilities in an issue.

Follow the instructions in `SECURITY.md` for responsible disclosure.

## Code of conduct

Be respectful and constructive when participating in project discussions,
issues, and pull requests.
